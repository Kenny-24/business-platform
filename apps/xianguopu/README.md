# 鲜果铺 Xianguopu · V6 精简购物体验版

一套可本地完整联调的精品水果微信小程序，包含原生小程序、Vue 管理后台、Fastify API、PostgreSQL 数据库与 36 款示例商品。本版按浅森林绿主题完成 11 个页面的视觉与交互重构，保留真机图片缓存、微信登录、直接购买、地址、礼赠、配送时段、订单和后台能力。

新版视觉与体验综合了国际优秀生鲜案例的长处：水果礼赠品牌的编辑感与品质表达、日系高端果店的留白和产地叙事、生鲜电商的时令/熟度信息、确定性的履约承诺，以及订阅型生鲜平台清晰直接的购物路径。所有页面、文案和素材均为本项目重新设计，没有复制第三方品牌资产。

## 新版功能

- 选果首页：搜索旁果篮入口、真实配送时段提示、场景快捷入口、分类探索与今日鲜选
- 水果图鉴：9 大品类、真实折扣/库存/包装条件与完整排序筛选面板
- 商品详情：产地与最佳时令一行展示、甜度/汁水、选果/熟度/保存指南
- 搜索：热词、历史记录、按水果名/品种/产地检索
- 购物车：选择、全选、增减、独立删除、礼赠包装、库存上限与真实商品推荐
- 下单链路：购物车结算或直接购买、登录、地址、配送时段、礼赠包装、独立用户备注、服务端重算金额、事务扣库存、订单状态
- 会员中心：微信登录、头像昵称编辑、订单、地址、顾问、品牌信息与退出登录
- 管理后台：商品、SKU、库存、订单礼赠标记、配送时段、首页服务范围、店铺设置与图片上传，包含加载/异常反馈与安全下架流程
- 订单一致性：服务端状态机校验、发货信息校验、取消订单幂等回补库存
- 会话韧性：登录态集中管理、过期自动续登、GET 请求瞬时失败自动重试一次
- 36 款统一风格的真实水果商品图，以及独立首页主视觉

## 本次体验升级

- 统一品牌色：浅森林绿 `#2F5F47`、奶油白 `#F7F3EA`、果实橙 `#E96D3D`
- 11 个页面使用同一套卡片、圆角、字号、间距、按钮和状态语义
- 独立时令/产地分包已移除；产地与最佳时令直接显示在商品卡和详情信息区
- 首页与结算页共用同一份配送时段数据，不展示无法兑现的下单截止承诺
- 商品卡收藏状态保存在本机，真实折扣才显示划线原价
- 首次进入采用与真实页面同形的骨架屏，不再使用遮挡操作的整页转圈
- 下拉刷新与地址/订单同步时保留旧内容，减少闪白和布局跳动
- 商品图使用懒加载、占位骨架和渐显；列表切换使用局部加载状态
- 静态设置与分类请求进行 5 分钟缓存，并合并并发中的重复请求
- 快速连续点击有路由锁、加购锁和提交锁，避免重复跳转、重复下单
- 关键操作提供轻触反馈；失败页面均提供明确原因和原地重试入口
- 首页仅在 Wi-Fi 环境预加载商品详情分包，避免额外消耗蜂窝流量
- 首页服务范围和履约说明由商户后台动态下发，不固定到特定城市
- 常用栏目提示、商品标签和个人中心辅助文案已提高字号与文字对比度
- 礼赠包装与期望配送时段写入独立订单字段，并在后台和订单详情中明确展示

## 项目结构

```text
xianguopu/
├─ miniprogram/       微信原生小程序（主包 + 分包）
├─ admin/             Vue 3 管理后台
├─ server/            Fastify API、Prisma 与静态商品图
├─ docker-compose.yml PostgreSQL 16
└─ project.config.json
```

## 环境要求

- Node.js 20 或更高版本
- npm 10 或更高版本
- Docker Desktop（推荐），或本机 PostgreSQL 16
- 微信开发者工具

## 快速启动

先进入解压后的项目根目录，也就是能看到 `miniprogram/`、`server/`、`admin/` 和 `project.config.json` 的目录。若放回原仓库，通常对应 `business-platform/apps/xianguopu`。

开始前可先运行不依赖第三方包的源码自检：

```bash
node scripts/verify.mjs
```

它会检查页面清单、JS/JSON/WXML/WXSS、36 款商品数据与图片、筛选/收藏/推荐结构、购物车行为，以及订单状态机关键规则。

### 1. 启动 PostgreSQL

```bash
docker compose up -d db
```

如果没有 Docker，也可以自行创建数据库 `xianguopu`，然后修改 `server/.env` 中的 `DATABASE_URL`。

### 2. 初始化并启动 API

```bash
cd server
cp .env.example .env       # 已存在 .env 时不要覆盖
npm install
npx prisma migrate deploy
npx prisma generate
npm run seed
npm run dev
```

API 默认地址：`http://127.0.0.1:8787`。健康检查：`http://127.0.0.1:8787/health`。

种子脚本可重复执行，会更新 9 个分类、36 款商品及 SKU，不会重复创建同名品种。

### 3. 启动管理后台

另开一个终端：

```bash
cd admin
npm install
npm run dev
```

后台默认地址：`http://127.0.0.1:5173`

本地管理员：

- 用户名：`admin`
- 密码：`FreshFruit@2026`

首次上线前必须修改密码和 `JWT_SECRET`。

### 4. 打开微信小程序

在微信开发者工具中直接导入项目根目录。根目录的 `project.config.json` 已配置：

```json
"miniprogramRoot": "miniprogram/"
```

开发阶段可在“详情 → 本地设置”中关闭合法域名校验。API 与图片地址在：

```text
miniprogram/config/env.js
```

本交付版已按你的局域网地址 `10.123.92.32` 配置。真机调试时确保手机和电脑在同一网络；电脑 IP 变化后需同步修改该文件。正式环境必须换成已备案的 HTTPS 域名并配置微信公众平台合法域名。

## 本地联调说明

- `WX_APPSECRET` 为空时，服务端使用 `dev_guest` 本地账号，方便直接走通登录、地址与下单。
- `PAYMENT_MODE=mock` 时，订单创建后直接标记为已支付，适合完整测试库存和订单流程。
- `CORS_ALLOWED_ORIGINS` 用逗号配置允许访问 API 的管理后台来源；原生小程序请求不依赖浏览器 Origin。
- 从旧版本升级时必须先执行 `npx prisma migrate deploy`，再执行 `npx prisma generate`；迁移会把旧备注里的礼赠包装和配送时段安全拆分到新字段。
- 管理后台的“下架”会保留商品、SKU 与历史订单快照；仍有关联商品的分类不能直接删除。
- 订单状态只能沿允许路径流转；发货必须填写物流信息，取消会在同一事务中回补库存且不会重复回补。
- 真实微信登录与支付只应在服务端配置密钥；不要把 AppSecret、商户私钥或 APIv3 Key 写进小程序。
- 前端从接口加载商品图，图片不会进入小程序主包。

## 生产上线前

1. 配置正式 `DATABASE_URL`、随机 `JWT_SECRET`、`WX_APPID`、`WX_APPSECRET` 和 `CORS_ALLOWED_ORIGINS`。
2. 将 API 与图片部署到 HTTPS 域名/CDN，并配置微信合法域名。
3. 将示例管理员密码替换为强密码，管理后台增加 MFA、SSO 或 IP 白名单。
4. 接入微信支付 JSAPI、支付回调验签与幂等处理。
5. 将本地 `public/uploads` 替换为 COS/OSS/S3 兼容对象存储。
6. 根据业务增加多仓、运费模板、可售区域、批次与物流接口。

更多技术边界见 [ARCHITECTURE.md](./ARCHITECTURE.md) 与 [DEPLOYMENT.md](./DEPLOYMENT.md)。
