# 鲜果铺架构说明

## 1. 设计目标

鲜果铺不是按城市绑定的本地水果日历，而是面向全国扩展的水果零售商城。核心数据关系是：

`分类 → 商品 → 多 SKU → 购买单位 → 库存 → 订单`

商品可以带品种和产地，但地域不是页面主导航，也不会限制未来扩展全国仓配。

## 2. 为什么小程序采用原生架构

为了尽量减少运行时框架层和跨层 diff，前端直接使用原生 WXML / WXSS / JavaScript：

- 全局启用 `renderer: skyline`
- 使用 `componentFramework: glass-easel`
- 使用 `lazyCodeLoading: requiredComponents`
- 商品详情、搜索、订单、地址拆分为 subpackages
- 主包仅保留四个 Tab 页和共享轻量组件
- 商品图片走远端静态资源/CDN，不打进主包
- 商品卡仅保留必要节点，避免深层嵌套
- 列表请求分页，上限 50 条/次
- 购物车只对变化项更新本地存储，不把整个商品详情写入页面 data

## 3. 包结构

### 主包

- `pages/home` 首页
- `pages/category` 分类
- `pages/cart` 购物车
- `pages/profile` 我的
- `components/product-card` 商品卡

### 分包

- `subpackages/product` 商品详情
- `subpackages/search` 搜索
- `subpackages/order` 结算/订单列表/订单详情
- `subpackages/address` 地址列表/编辑

进入首页时仅在 Wi-Fi 下预下载商品详情包；进入购物车时预下载订单包。

## 4. SKU 与单位设计

`Sku` 是价格和购买单位的真正载体，同一个水果可以同时存在多种购买方式。

例如苹果可以创建：

- 3斤装 / 箱 / ¥39.9
- 5斤装 / 箱 / ¥59.9
- 10斤装 / 箱 / ¥99

榴莲可以创建：

- 按斤称重 / 斤 / ¥39.9，`pricingMode=WEIGHT`

蓝莓可以创建：

- 125g/盒 / 盒
- 125g×4盒 / 提

数量控制还支持：

- `minPurchase` 最小购买数
- `step` 每次增减步长

因此后续可以实现 `0.5斤`、`2个起售`、`整箱起售` 等规则，而不需要改表结构。

## 5. 后端性能与一致性

API 使用 Fastify，数据访问使用 Prisma + PostgreSQL。

订单创建流程：

1. 校验用户和地址归属。
2. 批量查询 SKU。
3. 后端重新计算价格，绝不相信前端总价。
4. 校验最小购买数和库存。
5. 在数据库事务中使用条件更新扣减库存。
6. 任一 SKU 库存变化则整单回滚。
7. 创建订单和订单快照。

订单项保存 `name/image/spec/unit/price` 快照，避免以后修改商品名称或 SKU 后污染历史订单。

## 6. 安全边界

以下内容只能存在服务端：

- 微信 AppSecret
- JWT Secret
- 微信支付商户私钥
- APIv3 Key
- 数据库密码

小程序端只保存短期可撤销的登录 Token，不保存任何商户密钥。

图片上传目前写入服务端 `public/uploads`，适合开发和单机部署；生产环境应替换为 COS/OSS/S3 兼容对象存储并使用 CDN。

## 7. 全国销售扩展点

当前版本已经去掉本地化依赖。下一阶段可以在现有模型上增加：

- 多仓库 `Warehouse`
- SKU 分仓库存 `WarehouseStock`
- 省/市/重量阶梯运费模板
- 冷链/常温配送模板
- 不同地区可售范围
- 预售和到货日期
- 水果批次、采购成本和损耗
- 顺丰/京东物流/快递100等物流接口
- 优惠券和会员价

这些都不需要推翻当前商品与 SKU 模型。
