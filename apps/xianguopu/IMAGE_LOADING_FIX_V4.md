# 真机图片加载全局修复说明

## 问题原因

小程序主包默认使用 Skyline，而搜索、商品详情、订单和地址等页面可能使用 WebView。真机上的 WebView 直接读取局域网 HTTP 图片时可能失败，因此会出现接口与文字正常、同一张图在果篮可见、在其他页面却只显示灰色占位的情况。

## 本版处理

- 新增全局 `safe-image` 组件，所有业务图片统一由它渲染。
- 新增图片缓存层：先用小程序逻辑层 `wx.request` 获取二进制，再写入 `wx.env.USER_DATA_PATH`，页面只读取本地文件。
- 相同图片请求自动合并，全局最多同时下载 4 张，减少真机瞬间并发。
- 首次加载显示同尺寸骨架；缓存损坏时自动删除并重下；最终失败时可点击重试。
- 首页、分类、搜索、商品详情、果篮、结算、订单列表、订单详情和“我的”头像均已接入。
- 已反查全部 WXML：除 `safe-image` 组件内部外，没有页面直接使用原生 `<image>` 加载业务图片。

## 更新后的首次操作

1. 使用完整新目录导入微信开发者工具。
2. 选择“清缓存 → 全部清除”。
3. 重新编译，并重新建立真机调试连接。
4. 保持服务端 `npm run dev` 运行，手机与电脑连接同一 Wi-Fi。

当前真机联调地址仍为 `10.123.92.32:8787`。本次修复不改变数据库结构，无需重新迁移或重新导入商品数据。
